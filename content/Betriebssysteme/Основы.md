### Вызов fork()
Создает полную копию процесса(ребёнок). Становится  два  идентичных процесса.
fork() у родителя - выдает ID ребенка
fork() у ребенка  - выдает 0.
У ребенка своя память - перемена у родителя не поменяется.

#### Пример с Probeklausur
```
int main() {
    int i = 1;
    while (i != 3) {
        fork();
        ++i;
        printf("Prozess Nummer: %d\n", i);
    }
}
```
fork() создает  идентичный процесс, при первой итерации Output:
"_Prozess Nummer: 2_
_Prozess Nummer: 2_"

Вторая итерация, снова fork(), уже 4 процесса. Все увеличивают **i** до 3. Цикл заканчивается.
Итоговый Output:
"_Prozess Nummer: 2_
_Prozess Nummer: 2_
_Prozess Nummer: 3_
_Prozess Nummer: 3_
_Prozess Nummer: 3_
_Prozess Nummer: 3_"

### Scheduling
Когда процессов много, а ядер мало, ОС решает какой процесс идет некст.

Два важных алгоритма: **RMS**(Rate-Monotonic Scheduling)  и **EDF**(Earliest Deadline First)
#### RMS
Rate-Monotonic Scheduling
Чем чаще(Periode) процесс должен повторяться, тем выше приоритет.
Динамический, постоянно пересчитывается.

Пример: А запускается каждые 4мс, Б каждые 8мс.
#### EDF
Earliest Deadline First
Выбирают того у кого дедлайн ближе всего. (срочность)
Пример: дедлайн у процесса Б через 2мс, а у А через 5мс. 
У процессов есть 2 значения - частота и срочность(Это запас времени до критического момента). Датчик дыма редко, но должен завершиться за 1мс, без задержек.
#### Другие алгоритмы
**FCFS** - First come first serve.
**Round  Robin(RR)**  - Каждому даётся кусочек времени, не успел -> в конец очереди.
**SPN** - shortest process next.

### Synchronization
Когда несколько потоков работают с той же памятью - **Race Condition**. Это ситуация, когда результат программы зависит от того какой поток успел первым. *На экзамене спрашивают как из-за этого могут пропасть данные.*

Инструменты решения:
- **Mutex** - простой замок. Один поток взял ключ(lock), остальные ждут пока он его не принесет(unlock).
- **Semaphore** - счетчик ресурсов. 
  - sem_wait(): уменьшает счетчик. Если там - поток засыпает.
  - sem_post(): увеличивает счетчик и "будит" спящих. Вызывается всегда после sem_wait() и всей работы. Это не переключатель режимов читатель-писатель, они работают независимо. Это просто чтобы *если* есть "спящие" читатели/писатели чтобы они получили уведомление и проснулись для чтения/писания. 

**Кольцевой буфер** - массив у которого начало соединено с концом. Есть два указателя: write pointer, read pointer. Сбрасываем индекс через modulo [arraysize]и таким образом сдвигаем кольцо.
Семафоры это идеальный инструмент для управления кольцевым буфером в многопотоке.

Классическая задача - **Producer-Consumer**.
![[Pasted image 20260611001019.png]]
Две опасные ситуации:
- *Буфер переполнен:* Писатель может перезаписать данные которые Читатель ещё не успел прочитать.
- *Буфер пуст:* Читатель может прочитать мусор или старые данные.

**n** - (sem_full)- изначально равен 0.
**e** - (sem_empty) - равен размеру буфера.

Поток определяетсчя как Читатель или Писатель по тому, какой семафор он проверяет первым(через sem_wait(&...)).
- Писатель: ждёт пустоту, чтобы её заполнить
	  *sem_wait(&sem_empty);*
	  *sem_post(&sem_full);* Сигнализирует +1
- Читатель: ждёт данные, чтобы их забрать
	  *sem_wait(&sem_full);*
	  *sem_post(&sem_empty);* Сигнализирует -1

Писатель это может быть как один поток который 3 раза пишет(например для сложной задачи 3 ресурса забронировать), или 3 потока которые пишут по 1 разу. С читателем то же самое. Семафор это просто счётчик.
###### **Сценарий 1:**
`sem_empty = 3`
`n = 0`

`sem_wait(&e)` - П1
`sem_wait(&e)` - П2
`sem_wait(&e)` - П3

`sem_wait(&e)` -  Писатель 4 засыпает.

`sem_post(&n)` - Писатель 1 сигнализирует что написал и есть чё почитать.

`sem_wait(&n)` - Ч1 читает.
`sem_wait(&e)` - П5 засыпает, места всё ещё нету.
`sem_post(&e)` - Ч1 прочитал, появилось одно пустое место. П4 автоматически разбудился и начал писать, 
###### Сценарий 2
`e = 3`
`n = 0`

`sem_wait(&n)` - Ч1 блокируется, читать нечего. 

`sem_wait(&e)` - П1 пишет
`sem_post(&n)` - П1 написал. Ч1 разбудился и читает.
`sem_post(&e)` - Ч1 прочитал.

###### Код-пример для понимания
`#include <stdio.h>`
`#include <pthread.h>`
`#include <semaphore.h>`
`#include <unistd.h>`

`#define BUFFER_SIZE 2`

`int buffer[BUFFER_SIZE];`
`int write_index = 0;`
`int read_index = 0;`

`sem_t sem_empty; // Считает свободные ячейки (старт: 2)`
`sem_t sem_full;  // Считает заполненные ячейки (старт: 0)`

`// Поток-Писатель`
`void* producer(void* arg) {`
    `for (int i = 1; i <= 5; i++) {`
        `sem_wait(&sem_empty); // Ждем пустую ячейку`

        `buffer[write_index] = i; // Пишем данные`
        `printf("Писатель ЗАПИСАЛ: %d в ячейку %d\n", i, write_index);`
        `write_index = (write_index + 1) % BUFFER_SIZE; // Сдвиг по кольцу`

        `sem_post(&sem_full);  // Сообщаем Читателю: есть данные`
        `sleep(1);             // Имитация тяжелой работы`
    `}`
    `return NULL;`
`}`

`// Поток-Читатель`
`void* consumer(void* arg) {`
    `for (int i = 1; i <= 5; i++) {`
        `sem_wait(&sem_full);  // Ждем заполненную ячейку`

        `int data = buffer[read_index]; // Читаем данные`
        `printf("Читатель СЧИТАЛ: %d из ячейки %d\n", data, read_index);`
        `read_index = (read_index + 1) % BUFFER_SIZE; // Сдвиг по кольцу`

        `sem_post(&sem_empty); // Сообщаем Писателю: освободилось место`
        `sleep(2);             // Читатель работает медленнее Писателя`
    `}`
    `return NULL;`
`}`

`int main() {`
    `pthread_t prod_thread, cons_thread;`

    `// Инициализация семафоров`
    `sem_init(&sem_empty, 0, BUFFER_SIZE); // 2 пустых места`
    `sem_init(&sem_full, 0, 0);           // 0 заполненных мест`

    `// Запуск потоков`
    `pthread_create(&prod_thread, NULL, producer, NULL);`
    `pthread_create(&cons_thread, NULL, consumer, NULL);`

    `// Ожидание завершения потоков`
    `pthread_join(prod_thread, NULL);`
    `pthread_join(cons_thread, NULL);`

    `// Удаление семафоров`
    `sem_destroy(&sem_empty);`
    `sem_destroy(&sem_full);`

    `return 0;`
`}`
